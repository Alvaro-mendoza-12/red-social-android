## Prioridad de acceso tras reporte desde teléfono

El usuario volvió a observar «El servidor de Novvin no está disponible» tanto al iniciar sesión como al continuar recuperación. El servidor respondió desde una IP pública de Funnel en el puerto 8443: `/ready` HTTP 200, un login con identidad ficticia HTTP 404 `ACCOUNT_NOT_FOUND` y una solicitud de recuperación ficticia HTTP 200 `delivery: disabled`, cada uno en menos de un segundo. Esto ubica el fallo comunicado antes de la API o en la conectividad específica del dispositivo; no verifica las credenciales de una cuenta real.

La APK 3.3.10 usa el origen HTTPS estable fijado en la compilación para login, registro, renovación, cambio de contraseña y las rutas de recuperación. Tampoco condiciona las demás operaciones al sondeo previo de `/ready` cuando usan ese origen fijo: el servidor dará su propia respuesta o se mostrará el error de conexión real. Al arrancar, el origen estable sustituye un túnel temporal antiguo almacenado en el teléfono. Esto requiere instalar la APK nueva; un binario anterior no recibe esta corrección. El servidor ya recibió la transacción de recuperación y quedó saludable tras su reconstrucción.

Sin correo, la vía de autoservicio disponible es un código de recuperación guardado previamente fuera del teléfono. Una cuenta que perdió contraseña, todas sus sesiones y todos sus códigos carece de una prueba de identidad automática; no se puede conceder acceso seguro solo con el correo o nombre de usuario. Para cubrir ese caso habrá que configurar otro método verificable (por ejemplo, claves de acceso o verificación asistida), con registro previo o revisión de propiedad de la cuenta.
